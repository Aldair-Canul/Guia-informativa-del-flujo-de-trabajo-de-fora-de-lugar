          01
          
Las tres piezas

          
Cada una resuelve un problema distinto.

        


        

          

            
Godot

            
Motor de videojuegos gratuito y de código abierto, para 2D y 3D. Todo se arma con nodos agrupados en escenas. Se programa en GDScript, parecido a Python, o en C#.

            crear
          

          

            
Git

            
Control de versiones que vive en tu computadora. Guarda "fotos" del proyecto (commits) para volver atrás, y deja probar ideas en ramas sin tocar lo que ya funciona.

            guardar historial
          

          

            
GitHub

            
Sitio web que aloja repositorios de Git. Sirve de respaldo y de punto de encuentro del equipo, con pull requests para revisar cambios antes de juntarlos.

            compartir
          

        


        
Git es el programa; GitHub es un servicio que guarda una copia. Git funciona sin GitHub, pero GitHub no funciona sin Git.

      

    


    
    

      

        

          02
          
Seis pasos para arrancar

          
En orden. Cada uno termina con algo que ya funciona.

        


        
    
          
  1. 
            
    Instala Godot
    
            
    Descarga la versión estable 4.x desde godotengine.org. No se instala: es un ejecutable que abres directo. Para empezar, la versión estándar (GDScript).
    
          
    2. 
          
  2. 
            
    Instala Git
    
            
    Desde git-scm.com. Luego dile quién eres, una sola vez:
    
            
    
              
              
    git config --global user.name "Tu Nombre"
git config --global user.email "tu@correo.com"
git config --global init.defaultBranch main
    
            
    
          
    3. 
          
  3. 
            
    Crea tu cuenta de GitHub
    
            
    En github.com, con el mismo correo que pusiste en Git. Activa la verificación en dos pasos desde el principio.
    
          
    4. 
          
  4. 
            
    Crea un proyecto en Godot
    
            
    En el gestor de proyectos pulsa Crear, elige una carpeta vacía y el renderizador de compatibilidad, que es el más ligero. Haz una escena con un Node2D y un Sprite2D y córrela con F5.
    
          
    5. 
          
  5. 
            
    Inicia el repositorio
    
            
    Terminal dentro de la carpeta del proyecto, .gitignore primero (está más abajo) y después el primer commit.
    
            
    
              
              
    git init
git add .
git commit -m "Proyecto inicial de Godot"
    
            
    
          
    6. 
          
  6. 
            
    Súbelo a GitHub
    
            
    Conecta el repo local con uno remoto y publica. Los comandos están en la sección GitHub.
    
          
    7.

          04
          
Simulador de ramas

          
Cada círculo es un commit. Las líneas muestran de cuál viene.

        


        

          

            
            
            
            
          

          

          

          

        


        
    
          
  • Rama: línea de trabajo paralela. Sirve para probar algo sin romper lo que ya funciona.
    • 
          
  • Merge: junta una rama con otra y crea un commit con dos padres.
    • 
          
  • Límite: cuatro ramas como máximo, para que el dibujo se siga leyendo.

          05
          
Godot y Git juntos

          
Godot guarda escenas y recursos como texto, así que Git los entiende bien. Hay que configurar algunas cosas desde el inicio.

        


        

          
          
        


        

          

            
            
# Caché del editor de Godot 4 (se regenera sola)
.godot/
*.translation

# Exportaciones y compilados
export/
build/
*.apk
*.aab
*.exe
*.pck

# Credenciales de exportación
export_credentials.cfg

# Editor y sistema
.vscode/
.idea/
.DS_Store
Thumbs.db

          

        


        

          

            
            
# Finales de línea iguales en todos los sistemas
* text=auto eol=lf

# Archivos pesados con Git LFS
*.png  filter=lfs diff=lfs merge=lfs -text
*.jpg  filter=lfs diff=lfs merge=lfs -text
*.wav  filter=lfs diff=lfs merge=lfs -text
*.ogg  filter=lfs diff=lfs merge=lfs -text
*.ogv  filter=lfs diff=lfs merge=lfs -text
*.mp3  filter=lfs diff=lfs merge=lfs -text
*.glb  filter=lfs diff=lfs merge=lfs -text

          

          
Instala Git LFS y corre git lfs install una vez. En proyectos chicos es opcional; con arte, audio y video pesados deja de serlo.

        


        

          

            
Sí se sube

            
    
              
  • project.godot y las carpetas del juego
    • 
              
  • Escenas .tscn y recursos .tres
    • 
              
  • Scripts .gd y sus .uid (Godot 4.4 en adelante)
    • 
              
  • Los .import, junto a su asset
    • 
            

          

          

            
No se sube

            
    
              
  • La carpeta .godot/, que es caché local
    • 
              
  • Ejecutables y paquetes exportados
    • 
              
  • Contraseñas o llaves de firma
    • 
            

          

        


        
Hábitos que evitan conflictos

        

          
Commits pequeños
Un cambio por commit: "Agrega salto doble", no "cambios varios".

          
Una rama por tarea
Nombres como feat/enemigo-volador o fix/colision-pared.

          
Escenas chicas
Dos personas editando la misma escena a la vez es la causa número uno de conflictos. Divide el juego en muchas escenas pequeñas.

          
Tags de versión
git tag v0.1.0 marca una demo estable a la que puedes volver.

        

      

    


    
    

      

        

          06
          
Publicar en GitHub

          
Del repo local a la nube.

        


        
    
          
  1. Crea un repositorio vacío con el botón New. No marques README ni .gitignore: ya tienes los tuyos.
    2. 
          
  2. Copia la URL. HTTPS es lo más simple para empezar; SSH es más cómodo con el tiempo.
    3. 
          
  3. Conéctalo y publica la rama principal.
    4. 
          
  4. Autentícate. GitHub ya no acepta tu contraseña en la terminal: usa un Personal Access Token o Git Credential Manager.
    5. 
        


        

          
          

git remote add origin https://github.com/TU-USUARIO/mi-juego.git
git branch -M main
git push -u origin main

# el ciclo diario, a partir de aquí:
git switch -c tu-rama
git add .
git commit -m "Describe lo que hiciste"
git push -u origin tu-rama

# crea el Pull Request y confirma el Merge en
este momento tus cambios pasan oficialmente a
formar parte de la rama principal

# borra tu rama (opcionaL pero recomendado):
Una vez integrado, la misma página te mostrará
un botón para eliminar la rama remota(Delete branch),
ya que su trabajo terminó

# actualizar tu computadora:
git switch main 
git pull




        

        
Para colaborar: crea una rama, súbela con git push -u origin nombre-rama y abre un Pull Request. Alguien lo revisa antes de fusionarlo.

El ciclo de cada tarea

        
    
          
  1. main es lo que funciona. Nadie trabaja directo en ella.
    2. 
          
  2. Una rama por tarea, con prefijo según el tipo de cambio.
    3. 
          
  3. Commits con gitmoji y un mensaje que diga qué cambió.
    4. 
          
  4. Push y Pull Request. Todo entra a main por PR: llevamos más de 60.
    5. 
          
  5. Merge desde GitHub y de vuelta a main para empezar la siguiente.
    6. 
        

        

          
          
git switch main
git pull
git switch -c fix/cinematicas
# ...trabajas en Godot...
git add .
git commit -m ":bug: fix: Videos optimizados implementados en el juego"
git push -u origin fix/cinematicas
# abres el Pull Request en GitHub y se fusiona

    •

    • 
              
  • :sparkles: algo nuevo
    •

Lo que haríamos distinto

        
Al revisar el historial, esto es lo que nos falta pulir. Mejor aprender de nuestros errores que repetirlos.

        
    
          
  • 
            Los ejecutables viven en el repo.
            La carpeta EXPORTACIONES (builds de Web y Linux) pesa unos 104 MB y cada versión nueva se suma al historial. La carpeta .git ya ronda los 533 MB. Para builds es mejor usar GitHub Releases, y Git LFS para videos y arte pesado.
          
    • 
          
  • 
            Nombres de rama que no dicen nada.
            Junto a fix/cuarto conviven final, reduccion o MAFER, y se mezclan feat/ con feature/. Una regla escrita evita eso.
          
    • 
          
  • 
            Algunos mensajes no explican el cambio.
            Hay commits que solo dicen Bugs o un emoji. Dentro de un mes nadie recordará qué eran.
          
    • 
          
  • 
            El .gitignore ignora *.import,
            pero más de cien de esos archivos ya se rastrean. Lo recomendado en Godot 4 es subirlos y dejar fuera solo .godot/.
          
    • 
          
  • 
            No hay README en la raíz.
            Quien llegue al repo no sabe qué es ni cómo abrirlo. Dos párrafos y la versión de Godot bastan.

          09
          
Preguntas frecuentes

          
Las que casi todos tienen al empezar.

        


        

          

            ¿Necesito saber programar para usar Godot?
            
No para empezar. Puedes armar escenas y probar cosas con muy poco código. GDScript es de los lenguajes más amables para aprender y la documentación oficial tiene versión en español.

          

          

            Se llenó el repositorio de archivos raros, ¿qué pasó?
            
Seguramente se subió la carpeta .godot/. Agrégala al .gitignore, corre git rm -r --cached .godot para dejar de rastrearla y haz un commit.

          

          

            Me salió un conflicto en un .tscn, ¿qué hago?
            
Ábrelo en un editor de texto: verás marcas <<<<<<<, ======= y >>>>>>>. Elige qué versión conservar, borra las marcas, abre la escena en Godot para confirmar que carga y haz commit. Si se complica, git merge --abort te regresa al estado anterior.

          

          

            ¿Puedo deshacer un commit?
            
Sí. Si aún no lo subiste, git reset --soft HEAD~1 lo quita y deja tus cambios listos. Si ya lo subiste, usa git revert <id>, que crea un commit nuevo que lo cancela.

          

          

            ¿Todo esto es gratis?
            
Godot y Git son de código abierto. GitHub tiene un plan gratuito con repositorios privados, suficiente para proyectos personales y escolares.
